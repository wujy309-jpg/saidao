# 代码评审最佳实践

## 1. 评审维度

### 1.1 代码质量
- 可读性: 命名清晰、注释适当
- 可维护性: 结构清晰、职责单一
- 可测试性: 依赖注入、接口抽象
- 复用性: 避免重复、提取公共

### 1.2 代码规范
- 命名规范: 驼峰命名、常量大写
- 格式规范: 缩进、空行、长度
- 注释规范: 类注释、方法注释
- 导入规范: 顺序、分组

### 1.3 安全性
- 输入验证
- SQL注入防护
- XSS防护
- 敏感信息保护

### 1.4 性能
- 算法复杂度
- 数据库查询
- 缓存使用
- 资源释放

## 2. 常见问题

### 2.1 代码坏味道
- 长方法
- 大类
- 重复代码
- 过多参数

### 2.2 设计问题
- 职责不清
- 耦合过紧
- 缺少抽象
- 过度设计

### 2.3 安全漏洞
- 硬编码密码
- 未验证输入
- 日志泄露
- 权限不足

## 3. 评审流程

### 3.1 评审前
- 了解需求
- 熟悉代码规范
- 准备评审工具

### 3.2 评审中
- 整体结构
- 核心逻辑
- 边界条件
- 错误处理

### 3.3 评审后
- 记录问题
- 跟踪修复
- 总结经验

## 4. 评分标准

### 4.1 代码质量(40%)
- 90-100: 优秀，结构清晰，可读性强
- 80-89: 良好，基本规范
- 70-79: 一般，需要改进
- <70: 较差，需要重构

### 4.2 文档完整性(20%)
- 类注释完整
- 方法注释清晰
- 关键逻辑有注释

### 4.3 功能完整性(20%)
- 功能实现完整
- 边界条件处理
- 异常处理

### 4.4 代码规范(20%)
- 命名规范
- 格式规范
- 导入规范
