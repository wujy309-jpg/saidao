# 协作域安全复现与修复报告

## 结论

协作域剩余阶段已完成：团队生命周期可以创建、申请、审批、通知、转让和解散；项目空间提交会保存快照，并提供文件级 diff 与生成新提交的回滚；前端已接入角色控制和错误提示。

## 团队生命周期证据

| 场景 | 结果 |
|---|---|
| 创建团队 | 创建者从 JWT 成为唯一队长，客户端 `leader/memberCount/id` 被忽略 |
| 重复申请 | 已有待审批申请时拒绝再次申请 |
| 审批状态机 | 只有 `PENDING` 可以审批，已通过/已拒绝不能重复处理 |
| 人数与招募 | 达到上限自动关闭招募，移除成员后恢复招募 |
| 队长保护 | 队长不能退出或被移除，必须先转让或解散 |
| 队长转让 | 只能转让给现有成员，新旧队长都会收到通知 |
| 解散 | 清理申请、成员和项目关联；论坛招募帖保留但解除 `teamId` |

通知类型使用不超过旧数据库字段长度的稳定编码：`TEAM_APPLY`、`TEAM_APPROVED`、`TEAM_REJECTED`、`TEAM_REMOVED`、`TEAM_TRANSFERRED`、`TEAM_DISBANDED`。

## 版本沉淀证据

- 每次提交在 `repo_commit_files` 保存该分支的文本快照；二进制文件保存快照字节。
- `GET /api/code-repos/commits/{commitId}/files` 查看提交快照。
- `GET /api/code-repos/commits/{commitId}/diff` 返回 `ADDED/MODIFIED/DELETED` 文件级差异。
- `POST /api/code-repos/{repoId}/commits/{commitId}/rollback` 根据快照恢复文件，并生成新的回滚提交。
- 提交、分支、仓库和操作者会再次校验归属；没有快照的历史提交不会被盲目回滚。

## 已知边界

部署前创建的旧提交没有快照记录，回滚接口会拒绝这类提交并提示无法安全回滚；部署后产生的提交具备完整快照。大型历史二进制文件需要重新上传后才能获得可回滚快照。
