# 协作域权限矩阵（阶段 0/1）

## 角色定义

| 身份 | 说明 |
|---|---|
| OWNER | 仓库所有者 |
| DEVELOPER | 可修改文件、提交和创建分支的成员 |
| VISITOR | 只读成员，接口角色为 `GUEST` 或 `REPORTER` |
| 非成员 | 没有该仓库成员记录的登录用户 |
| ADMIN | 平台管理员；删除仓库可执行平台级操作，但不能伪造普通用户身份 |

## 请求样例

以下命令中的 `$BASE`、`$TOKEN`、`$REPO_ID`、`$BRANCH`、`$PATH` 由验收环境提供。所有请求都应使用登录 JWT：

```bash
curl -i "$BASE/api/code-repos/$REPO_ID"
curl -i "$BASE/api/code-repos/$REPO_ID/members"
curl -i "$BASE/api/code-repos/$REPO_ID/branches"
curl -i "$BASE/api/code-repos/$REPO_ID/files?branch=$BRANCH" \
  -H "Authorization: Bearer $TOKEN"
curl -i "$BASE/api/code-repos/$REPO_ID/files/download?branch=$BRANCH&path=$PATH" \
  -H "Authorization: Bearer $TOKEN"
```

写操作必须使用登录态，不再传操作者身份字段：

```bash
curl -i -X POST "$BASE/api/code-repos/$REPO_ID/commits" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"branchId":1,"message":"update","files":[{"path":"src/main.py","content":"print(1)","deleted":false}]}'
```

## 安全负例

- 在请求体增加或修改 `ownerId`、`authorId`、`inviterId`，不能改变当前操作者。
- `branch=../../static`、`branch=repo/main` 等值必须被拒绝。
- `path=../../app/static/x.html`、`path=/tmp/x` 等值必须被拒绝。
- 非成员访问 `files`、`files/download`、`commits` 必须返回 `403`。
