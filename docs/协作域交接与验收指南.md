# 协作域交接与验收指南

> 适用提交：`b960576 feat: 完善团队协作与项目空间能力` 及其后续提交。

## 1. 交接结论

本次完成了赛道平台的协作域闭环：**组队、团队管理、项目空间权限控制、提交快照、文件差异和版本回滚**。所有修改已合并到远程主分支 `main`。

核心流程如下：

```text
创建团队 -> 申请加入（附说明） -> 队长审批 -> 团队通知
-> 项目空间协作 -> 提交文件 -> 查看 diff -> 回滚到历史快照
-> 转让队长 / 解散团队
```

## 2. 本次交付范围

### 团队组队

- 创建团队时由当前登录用户自动成为队长，客户端不能篡改 `leader`、`id` 或成员数。
- 成员可提交带申请说明的入队申请；队长在团队详情页能完整查看申请说明并审批。
- 同一用户不能重复待审批申请，也不能重复成为成员；已处理的申请不能再次审批。
- 团队满员时自动关闭招募；移除成员后可恢复招募。
- 队长不能直接退出或被移除，需先转让队长或解散团队。
- 支持转让队长，且新队长必须是现有成员。
- 团队申请、审批、拒绝、移除、转让、解散均会产生站内通知。
- 解散团队会清理成员、申请和项目空间关联；论坛招募帖保留，但会解除团队绑定。

### 项目空间安全与权限

- 所有操作者身份从 JWT 获取，不再接受请求体的 `ownerId`、`authorId`、`inviterId` 等身份字段。
- 仓库成员角色：`OWNER`、`MAINTAINER`、`DEVELOPER`、`REPORTER`、`GUEST`。
- 所有者和维护者可管理成员；所有者、维护者、开发者可写文件、提交、创建分支；报告者和访客只读。
- 非成员访问仓库详情、文件、下载、提交历史均返回 `403`。
- 分支名、文件路径和上传磁盘路径均做了边界校验，拒绝路径穿越。
- 仓库、成员、团队、申请等响应已改为公开 DTO，不返回密码、手机号、学号、邮箱等敏感字段。
- 团队、仓库、成员、分支和提交等敏感操作会写入审计日志。

### 提交历史与版本回滚

- 每个新提交保存分支的文件快照；文本文件保存内容，二进制文件保存字节数据。
- 支持查看提交文件清单和文件级 `ADDED`、`MODIFIED`、`DELETED` 差异。
- 支持恢复到指定提交快照；恢复会生成一条新的回滚提交，不会删除原有历史。
- 提交归属、分支归属和操作者权限均会再次验证。

### 前端体验

- 团队详情页包含完整申请说明、审批、移除成员、转让队长和解散操作。
- 通知页支持团队相关通知。
- 项目空间页按角色展示可用操作，支持提交详情、diff 和回滚。
- 前端统一处理 `401`、`403`、`409` 等错误提示。

## 6. 手工验收步骤

### 6.1 团队生命周期

使用两个浏览器窗口或一个普通窗口加一个无痕窗口，以保证不同账号会话隔离。

1. 用 `student01` 登录，进入“团队广场”，创建一个人数上限为 3 的测试团队。
2. 用 `student02` 登录该团队详情，点击“申请加入”，输入多行申请说明，例如：

   ```text
   我是计算机专业二年级学生。
   熟悉 Python 和前端开发，希望负责数据处理与页面实现。
   ```

3. 切回 `student01` 并刷新团队详情。应看到“入队申请”区块，申请说明完整显示且保留换行，不应被单行截断。
4. 用 `student01` 点击“通过”，切回 `student02` 检查通知页，应出现 `TEAM_APPROVED` 通知。
5. 切回 `student01`，点击“转让队长”，选择 `student02` 并确认。
6. 两个账号的通知页都应出现 `TEAM_TRANSFERRED`；团队详情的队长应变为 `student02`。
7. 验证原队长不能再编辑、移除成员或解散团队；新队长可以操作。
8. 以新队长解散团队。团队成员、申请及项目空间关联会被清理；若团队关联了论坛招募帖，帖子应保留但不再绑定该团队。

额外边界检查：

- 已申请用户再次申请，应收到“等待队长审批”的错误。
- 已通过或已拒绝的申请再次审批，应失败。
- 队长点击“退出团队”或被移除，应失败。

### 6.2 项目空间角色权限

1. 使用 `student01` 创建测试项目空间，默认分支为 `main`。
2. 在成员管理中添加 `student02` 为 `DEVELOPER`，添加 `student03` 为 `REPORTER` 或 `GUEST`。
3. 使用三个账号分别验证下表。

| 操作 | OWNER | DEVELOPER | REPORTER/GUEST | 非成员 |
|---|---:|---:|---:|---:|
| 查看仓库、成员、分支、文件 | 允许 | 允许 | 允许 | `403` |
| 下载文件 | 允许 | 允许 | 允许 | `403` |
| 上传、保存文件、提交、建分支 | 允许 | 允许 | `403` | `403` |
| 添加/移除成员、修改角色 | 允许 | `403` | `403` | `403` |
| 删除仓库 | 允许 | `403` | `403` | `403` |

前端同样应隐藏无权限操作；即使手工调用接口，后端也必须拒绝。

### 6.3 提交、diff 和回滚

以 `student01` 或 `student02` 在同一项目空间操作：

1. 第一次提交：创建 `README.md`，内容为 `version 1`。
2. 第二次提交：把 `README.md` 修改为 `version 2`，并新增 `docs/plan.md`。
3. 打开第二次提交的详情和 diff，预期同时看到：
   - `README.md` 为 `MODIFIED`，显示修改前后内容；
   - `docs/plan.md` 为 `ADDED`。
4. 对第一次提交执行回滚。
5. 当前文件应恢复为第一次提交时的内容，`docs/plan.md` 被删除，并且提交历史新增一条回滚提交。

## 7. 自动化权限验收

脚本路径：`scripts/collab-domain-acceptance.sh`。

先通过登录接口获取四个账号的 JWT：

```bash
BASE=http://127.0.0.1:8080/api

curl -sS -X POST "$BASE/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"student01","password":"student123"}'
```

响应中的 Token 位于 `.data.token`，用户 ID 位于 `.data.user.id`。准备好一个仓库后，为 OWNER、DEVELOPER、VISITOR 和非成员分别设置变量：

```bash
export OWNER_TOKEN='...'
export DEVELOPER_TOKEN='...'
export VISITOR_TOKEN='...'
export NON_MEMBER_TOKEN='...'
export OWNER_ID='student01 的用户 ID'
export REPO_ID='测试仓库 ID'
export BRANCH='main'
export FILE_PATH='README.md'

bash scripts/collab-domain-acceptance.sh
```

脚本会检查：

- 角色读写权限与成员管理权限；
- 非成员读取文件、下载文件、查看提交被拒绝；
- 访客提交和开发者管理成员被拒绝；
- 试图把角色改为 `OWNER` 被拒绝；
- `branch` 与 `path` 路径穿越被拒绝；
- 创建仓库时篡改 `ownerId` 不会改变实际所有者。

所有检查通过时，末尾输出：

```text
Acceptance matrix completed.
```

## 8. 重要接口

### 团队

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/teams` | 创建团队 |
| `POST` | `/api/teams/{teamId}/apply` | 提交入队申请，Body：`{"message":"..."}` |
| `GET` | `/api/teams/{teamId}/applications` | 队长查看申请（包含 `message`） |
| `POST` | `/api/teams/{teamId}/applications/{applicationId}/review` | 审批，Body：`{"approve":true}` |
| `POST` | `/api/teams/{teamId}/transfer-leadership` | 转让队长，Body：`{"newLeaderId":123}` |
| `DELETE` | `/api/teams/{teamId}` | 队长解散团队 |

### 项目空间与版本

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/code-repos` | 创建项目空间，所有者从 JWT 取得 |
| `POST` | `/api/code-repos/{repoId}/members` | OWNER/MAINTAINER 添加成员 |
| `POST` | `/api/code-repos/{repoId}/commits` | 创建提交 |
| `GET` | `/api/code-repos/commits/{commitId}/files` | 查看提交快照文件 |
| `GET` | `/api/code-repos/commits/{commitId}/diff` | 查看文件级差异 |
| `POST` | `/api/code-repos/{repoId}/commits/{commitId}/rollback` | 生成回滚提交 |

## 9. 已知边界与后续建议

- 团队公告或团队讨论入口是计划中的可选需求，尚未实现。
- 本次上线前的旧提交没有文件快照。对这类旧提交执行回滚时接口会拒绝，避免误删当前文件；新提交均有快照。
- 大型历史二进制文件只有在重新上传并产生新提交后才具备完整回滚快照。
- Docker 部署前应在运行环境提供 `JWT_SECRET` 和 `DB_PASSWORD`。`DEEPSEEK_API_KEY` 为可选，不影响协作域验收。
- 继续修改团队或仓库响应时应复用 `TeamDtos`、`RepoDtos` 与 `UserBrief`，避免重新序列化完整 `User` 实体。
