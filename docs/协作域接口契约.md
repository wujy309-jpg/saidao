# 协作域阶段 0 接口契约

## 项目空间角色

| 角色 | 读取仓库/成员/分支/文件/提交 | 上传和保存文件 | 提交/创建分支 | 成员管理 | 删除仓库 |
|---|---:|---:|---:|---:|---:|
| OWNER | 是 | 是 | 是 | 是 | 是 |
| DEVELOPER | 是 | 是 | 是 | 否 | 否 |
| VISITOR | 是 | 否 | 否 | 否 | 否 |
| 非成员 | 否 | 否 | 否 | 否 | 否 |

仓库当前实现中的 `MAINTAINER` 作为 OWNER 等价的管理角色，`REPORTER` 按 VISITOR 处理。管理员可以执行删除等平台级操作，但仍不能伪造普通用户身份。

## 身份来源

- 当前用户 ID 必须来自 JWT `Authentication.getPrincipal()`。
- `ownerId`、`userId`、`authorId`、`inviterId` 等请求字段不能决定操作者身份。
- 请求中的目标用户 ID 只允许在成员管理场景作为“被邀请/被修改对象”，且需要当前用户具备 OWNER 权限。

## 冻结的跨域约定

- 团队和仓库对外响应逐步使用 `UserBrief`，不直接返回完整 `User`。
- `UserBrief` 只包含 `id`、`name`、`reputation`、`role`。
- 团队申请状态为 `PENDING`、`APPROVED`、`REJECTED`。
- 论坛与团队使用 `teamId` 弱引用，协作域不依赖论坛实体。
- 通知由公共 `NotificationService` 提供，团队域只调用接口。

## 阶段 1 验收

- 同一仓库使用 OWNER、DEVELOPER、VISITOR、非成员分别访问同一组接口，结果符合上表。
- 非成员访问项目文件、下载和提交历史返回 `403`。
- 创建、上传、提交等操作不能通过修改请求体用户 ID 伪造操作者。
